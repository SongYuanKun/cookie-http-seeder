## 2. 单目录单实例

运行 `serve` 时，先持有数据目录内 `.receiver.lock` 的操作系统文件锁，直到服务结束。
新版本的第二个接收进程即便使用不同端口，也会明确报错退出；不同目录可以独立运行。
正常停止时先等待已接受的请求线程结束，再释放锁；进程退出或崩溃由操作系统释放锁。锁文件本身不会删除；不要把“文件存在”等同于进程存活，
也不要在服务运行中手工删除、替换该文件。

使用 POSIX flock / Windows msvcrt 字节锁，不引入运行时第三方依赖。
这是本地文件系统的协作锁，不是分布式锁；不支持用 NFS/SMB 等共享盘组成多写入节点。
直接调用底层存储函数、手工修改文件、未实现此锁的旧版进程不受保护。
升级时应先停止旧服务。`status` 等只读命令不需要独占锁。

## 3. 网站状态面板

网站管理表格现在直接分开显示：

- 来源启用状态、本机应用授权、Chrome 域名权限。
- 同步队列状态及下次尝试时间。
- 快照数量、新鲜度、最近接收/内容更新时间。
- 爬虫反馈：未验证、最近报告有效、报告登录失效、验证异常、结果过期。

点击“刷新授权 / 同步 / 登录状态”更新；加载配置、授权、撤销、推送后也会刷新。

显示沿用设备当地时间 `YYYY-MM-DD HH:mm:ss`，协议/文件的原始时间仍保持不变。

## 4. 单来源授权与撤销

“仅授权此来源”只改变浏览器权限和本机同意记录，不重新保存接收端配置，因此不会清空快照。
暂停中的来源须先启用，不能靠重新授权跳过服务端暂停。

“撤销本机授权”无需接收端在线即可使用，先持久化撤销，再通知后台清理待处理队列。
离线打开管理页时，可显示当前连接绑定的本机已授权来源缓存；该视图只允许撤销，不能修改服务端配置或重新授权。
本机缓存不代表接收端的全部来源，也不会据此假定接收端当前登录态。
随后尝试移除不再需要的可选域名权限；与其他来源、接收端共用的父/子域权限，以及必需权限保留。
权限清理失败不回滚本机撤销，页面会说明该情况。
撤销不会删除浏览器 Cookie，也不会清空接收端副本；要清空远端，请使用“清空并暂停”。
尚在采集的任务会在提交前再次检查授权；已经发出的网络请求不能撤回。
多个设置页/后台对连接和授权的修改使用 Web Locks 串行化，避免其他来源的更新复活被撤销的授权。

## 验证与边界

新增测试覆盖导入启动、Origin 拒绝、配置冲突 409、上传前置条件、鉴权先于正文读取、
锁竞争/异常释放/进程终止恢复，以及授权撤销/共用权限/并发变更/采集中撤销/状态展示。
Chrome API 的自动测试使用 mock，不能替代真实浏览器的授权弹窗与后台唤醒联调。
新增文件锁含 Windows 实现，当前主要 CI 平台仍为 Linux；Windows/macOS 实机仍需验证。

多 profile、独立设备 Token、分区 Cookie、多浏览器兼容仍不属于本次实现。
仍不读取 localStorage、不自动登录、不处理验证码、不保证跨环境会话对所有网站有效。

人工验收：启动接收端；加载扩展；添加测试站点并授权；推送后刷新状态；撤销本机授权；
确认不会自动再推送且接收端文件保留；单独重新授权，确认该动作不清空快照。
再尝试使用同一数据目录在另一端口启动第二个接收端，应立即提示目录已被占用。
