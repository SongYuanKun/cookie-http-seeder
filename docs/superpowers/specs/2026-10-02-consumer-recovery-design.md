# 爬虫接入与登录恢复设计

用户目标：完成此前开发清单，推送 main，并通知 grok bot 更新 Chrome 插件客户端。
使用场景是个人多电脑浏览器同步到一个接收端，自己的爬虫显式选择标签消费。

## 约束

- Python 3.11+、Chrome 120+、Node 22；运行时保持 Python 标准库，无新增依赖。
- 保留 V2 快照、CAS、显式域名授权、default 历史路径和共享 Token。
- Cookie/Header/Token/响应正文不进入诊断、反馈、队列、通知或事件日志。
- 每个请求按实际 URL 选 Cookie；不自动跟随重定向，不自动切换账号或标签。
- 不自动登录；HTTP 200/403 本身不能证明登录状态。
- 新的自动恢复和浏览器登录提醒默认关闭；401/403/授权/配置错误不自动恢复。

## 消费端

新增 `consumer.py`：`Observation(result, reason_code)` 校验现有枚举；
`ResponseRules` 从显式正文标记/JSON字段/登录重定向规则判断，未知响应报告 error。
`CookieConsumer` 原子读取 Header 与版本，调用用户提供的请求函数和判定函数。
确认 invalid 的版本后拒绝再次请求同一版本，新版本仅允许验证请求，valid 后恢复。
反馈旧版本 409 记为 discarded；反馈联网失败记为 pending，并可有界重试，不能改变真实请求结果。
暂停状态持久化为根目录对应标签下的无凭据小文件，使爬虫重启后保持暂停。
等待新版本有超时/轮询间隔，不等待无限时长；清空或缺失快照不视为恢复。
完整 CLI 示例使用标准库、显式规则文件，可与实际爬虫共用 helper。
具体贝壳/房天下接口规则需实际消费者提供，不能虚构站点响应。

## 接收端

来源增加可选 `stale_after_seconds`、`validation_ttl_seconds`，范围 60–2592000 秒，
缺省均为 86400。仅修改阈值不清空 Cookie；实际 Cookie 作用域或原有配置修改仍遵守清空规则。
新增鉴权 `GET /v1/senders` 和 `status --all-senders`，汇总已初始化标签的无凭据状态，
不创建标签、不切换读取策略，损坏单个标签返回该标签错误而不中断全部汇总。
接收进程每分钟检查已存在且启用的来源，stale 提醒按标签/来源持久化 15 分钟冷却；
没有 webhook 或关闭通知时不预留冷却，不发送外部消息。
服务停止时停止检查器；测试不访问真实 webhook。

## 扩展

可选 `recoveryProbeMinutes`（0关闭，15–10080分钟）：仅临时错误耗尽后以低频探测接收端。
成功探测仍检查配置/授权，重新采集；失败保留 exhausted 并安排下一次低频探测。
每次探测最多触发一次快照尝试，不补满五次预算；401/403/配置/授权错误转 blocked。
探测时间持久化、worker 重建 alarm、切换连接/撤销授权/关闭设置取消旧探测。
可选 `loginPollMinutes`（0关闭，15–10080分钟）：轮询当前授权来源的反馈，
对新的 invalid/expired/stale 状态发本地通知，按来源去重，连接切换清理，通知不包含正文。
管理页增加来源阈值、恢复/提醒设置和只读全标签概览。
